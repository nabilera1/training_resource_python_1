| 평가 요소 | 상 | 중 | 하 | 평가 역량 | 지도 유의사항 및 피드백 |
| --- | --- | --- | --- | --- | --- |

## 수행평가 채점 기준표 (학교 계획 「알고리즘 문제 프로그래밍하기」)

평가 방법: 실험·실습, 프로젝트 / 교사 관찰 및 기록

| 채점 요소 | 수행 수준 | 세부 기준 | 배점 |
| --- | --- | --- | --- |
| 문제 분해 및 추상화 (20) | A·B | 복잡한 실생활 문제를 스스로 분석하여 입력, 처리, 출력의 단계로 정확히 분해하고, 각 단위 문제 간의 연관성을 논리적으로 모델링함 | 20 |
|  | C·D | 입력, 처리, 출력의 단계로 분해하고, 각 단위 문제 간의 연관성을 부분적으로 모델링함 | 15 |
|  | E | 도움을 받아 분석 및 분해하고, 일부 모델링함 | 10 |
| 다차원 데이터 구조의 적용 (25) | A | 2차원 리스트, 딕셔너리 자료구조를 활용하여 효율적으로 문제를 해결함 | 25 |
|  | B | 2차원 리스트, 딕셔너리 자료구조를 활용하여 문제를 해결함 | 20 |
|  | C | 2차원 리스트, 딕셔너리 자료구조를 활용하여 일부 문제를 해결함 | 15 |
|  | D | 2차원 리스트, 딕셔너리 자료구조 활용 시 도움을 받아 문제를 해결함 | 10 |
|  | E | 2차원 리스트, 딕셔너리 자료구조를 활용하지 않고 문제를 해결함 | 5 |
| 복합 제어 구조의 설계 (20) | A·B | 중첩 반복문과 다중 조건문을 설계하고 처리하며, 목적에 맞는 프로그램을 작성함 | 20 |
|  | C·D | 중첩 반복문과 다중 조건문을 부분적으로 설계하고 처리하며, 도움을 받아 프로그램을 작성함 | 15 |
|  | E | 중첩 반복문과 다중 조건문을 부분적으로 이해하고, 도움을 받아 일부 작성함 | 10 |
| 프로그램 구현 및 최적화 (20) | A·B | 예외 상황까지 완벽하게 처리하며, 목적에 맞는 효율적인 프로그램을 작성함 | 20 |
|  | C·D | 예외 상황까지 일부 처리하며, 도움을 받아 목적에 맞는 프로그램을 작성함 | 15 |
|  | E | 예외 상황까지 일부 처리하며, 도움을 받아 부분적으로 프로그램을 작성함 | 10 |
| 산출물 완성도 (15) | A·B | 프로그램 산출물을 정확한 위치에 저장하고 제출함 | 15 |
|  | C·D | 프로그램 산출물을 도움을 받아 해당 위치에 저장하고 제출함 | 10 |
|  | E | 프로그램 산출물을 해당 위치에 도움을 받아 부분적으로 저장하고 제출함 | 5 |

- 기본점수(수업과 수행평가에 참여하였으나 산출물이 없는 경우): 35점
- 인공지능(AI)은 소스코드 작성, 오류 수정 범위에서만 활용할 수 있으며, 활동지 서식에 활용 과정을 표기한다.
- AI 입력창에 본인이나 타인의 학번, 이름, 학교명 등 개인정보를 입력해서는 안 된다.
- AI 생성물을 그대로 제출하거나, 결과물의 내용을 묻는 교사의 질의에 적절히 답하지 못하는 경우 해당 내용은 채점에서 제외될 수 있다.

## 차시별 형성평가 체크리스트 (교사 관찰)

| 차시 묶음 | 관찰 포인트 | 상 | 중 | 하 |
| --- | --- | --- | --- | --- |
| 1~4 (발견·구조화·설계) | IPO 분석, 분해 트리, 순서도 | 스스로 정확히 | 일부 도움 | 예시를 보고 따라 함 |
| 5~7 (리스트·반복) | 리스트·for·문자열 활용 | 코딩 테스트 2문항 해결 | 기본 문항 해결 | 예제 코드 수정 수준 |
| 8~12 (함수·자료구조) | 함수 설계표, 딕셔너리·2차원 리스트 | 설계 → 구현 일치 | 구현은 했으나 설계 미흡 | 도움 받아 일부 구현 |
| 13~17 (클래스·핑퐁) | 객체 관계 설명, 상수 실험 | 구조도를 그리고 기능 수정 | 상수 수정·실행 | 실행 확인 수준 |
| 18 (테스트) | 정상·경계·예외 케이스 설계 | 7개 이상, 실패 원인 분석 | 5개 이상 | 도움 받아 작성 |

## 성취수준과 학교생활기록부 기재 예시

> 아래 문장은 예시이며, 실제 관찰 내용에 맞게 수정하여 사용합니다.

- (상) 업다운 게임의 입력 검증 문제를 정상·경계·예외 테스트 케이스로 찾아내고, 검사 로직을 함수로 분리한 뒤 자동 테스트로 회귀 검증함. 모둠 프로젝트에서 핑퐁 게임에 AI 패들과 난이도 설정 딕셔너리를 추가하고 상태 다이어그램과 코드의 일치를 근거로 설계 변경 이유를 논리적으로 발표함.
- (중) 가위바위보 판정을 2차원 리스트 판정표로 모델링하여 조건문을 단순화함. 테스트 결과표를 작성하여 공백 입력 오류를 찾아 strip()으로 수정함.
