> **5부 테스트·프로젝트·공유** · 22차시 · 6단계 모형: **공유·확장**  
> 게임: 갤러리 워크 · 발표 · 동료 평가 · 위키독스/깃허브 공유  
> 핵심 개념: 갤러리 워크, 발표, 동료 평가, 성찰, 공유, 오픈소스, 저작권

## 학습 목표

1. 완성한 게임을 시연하고 설계·구현·테스트 과정을 발표할 수 있다.
2. 동료의 게임을 평가 기준에 따라 피드백할 수 있다.
3. 프로젝트 전 과정을 성찰하고 확장 방향을 제안할 수 있다.

## 핵심 질문

> **우리가 만든 게임과 문제 해결 과정을 다른 사람에게 어떻게 전하고, 다음에는 무엇을 더 할 수 있을까?**

마지막 차시입니다. 각 모둠은 게임을 시연하고, 다른 모둠은 직접 플레이하며 피드백합니다. 발표는 '게임 자랑'이 아니라 **문제를 어떻게 분해하고, 설계하고, 테스트했는지**를 보여 주는 자리입니다.

## 발표 구성 (3분)

| 순서 | 내용 | 시간 |
| --- | --- | --- |
| 1 | 게임 소개와 문제 정의 (왜 만들었나?) | 30초 |
| 2 | 시연 (핵심 기능 위주) | 1분 |
| 3 | 핵심 코드 1개 설명 (데이터 구조 또는 알고리즘) | 40초 |
| 4 | 가장 의외였던 버그와 해결 방법 | 30초 |
| 5 | 다음에 추가하고 싶은 기능 | 20초 |

## 갤러리 워크와 동료 평가

모둠별 노트북에 게임을 띄워 두고, 다른 모둠이 돌아다니며 직접 플레이합니다.

| 평가 항목 | ★(1~3) |
| --- | --- |
| 규칙이 이해하기 쉽고 게임이 재미있다 |  |
| 이상한 값을 입력해도 멈추지 않는다 |  |
| 코드가 함수/클래스로 잘 나뉘어 있고 주석이 있다 |  |
| 리스트·딕셔너리·2차원 리스트를 알맞게 썼다 |  |
| 차트와 실제 프로그램이 일치한다 |  |

피드백은 **칭찬 1 + 제안 1**로 구체적으로 씁니다. (예: "판정표를 2차원 리스트로 만든 점이 좋아요. 난이도 선택이 있으면 더 좋겠어요.")

## 공유하기: 깃허브와 위키독스

이 책의 모든 소스코드와 자료는 깃허브에 공개되어 있고, 위키독스에서 읽을 수 있습니다.
여러분의 작품도 **패들렛·퀴즈앤보드** 등 학급 공유 공간이나 깃허브에 올려 공유할 수 있습니다.

공유할 때 지킬 것

- 다른 사람의 코드·이미지·소리를 썼다면 **출처**를 밝힙니다.
- 코드나 화면에 **이름, 학번, 학교 등 개인정보**를 넣지 않습니다.
- AI의 도움을 받았다면 **어떻게 활용했는지** 함께 적습니다.

### 문제 1. 동료 평가 집계 (기본)

첫째 줄에 평가자 수 n, 다음 n줄에 5개 항목의 별점(1~3)이 공백으로 주어집니다. 항목별 평균을 소수 첫째 자리까지 공백으로 구분해 출력하고, 둘째 줄에 평균이 가장 낮은 항목 번호(1부터, 같으면 앞 번호)를 `보완 항목: ○`으로 출력하세요.

- 입력: n, n줄의 별점 5개
- 출력: 항목별 평균, 보완 항목

예제 입력 1

```text
3
3 2 3 2 3
3 1 2 3 3
2 2 3 2 3
```

예제 출력 1

```text
2.7 1.7 2.7 2.3 3.0
보완 항목: 2
```

### 문제 2. 리그 순위표 (도전)

모둠 대항 핑퐁 리그입니다. 첫째 줄에 경기 수 n, 다음 n줄에 `팀A 점수A 팀B 점수B`가 주어집니다. 이기면 승점 3, 비기면 1, 지면 0입니다. 승점이 높은 순으로, 같으면 팀 이름 사전순으로 `팀 승점`을 출력하세요.

- 입력: n, n줄의 경기 결과
- 출력: 순위표

예제 입력 1

```text
3
red 5 blue 3
blue 5 green 5
green 5 red 2
```

예제 출력 1

```text
green 4
red 3
blue 1
```
