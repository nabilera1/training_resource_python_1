| 프로젝트 목표 | 1. 게임 규칙을 입력·처리·출력의 하위 문제로 분해하고, 각 하위 문제를 매개변수와 반환값이 있는 함수로 설계할 수 있다.<br>2. 게임의 규칙과 기록을 딕셔너리·2차원 리스트로 모델링하여 조건문을 줄이고 확장하기 쉬운 프로그램을 작성할 수 있다.<br>3. 중첩 반복문과 다중 조건문을 활용하여 표 형태의 데이터를 처리하고, 기존 코드를 함수 구조로 리팩터링할 수 있다.<br>4. 테스트 케이스로 프로그램을 검증·개선하고, 결과물을 공유하며 동료 피드백을 반영할 수 있다. |  |  |

## Ⅲ. 7차시 수업 지도안 – 2차원 리스트와 딕셔너리로 가위바위보 판정표 게임 만들기(구현 단계, 50분 / 수업 모형: PRIMM + 짝 프로그래밍)

2. 프로그램 코드 (핵심 부분)  
CHOICES = ["가위", "바위", "보", "도마뱀", "스팍"]  
BEATS = {"가위": ["보", "도마뱀"], "바위": ["가위", "도마뱀"],      # 이기는 쪽: [지는 쪽 2개]  
         "보": ["바위", "스팍"], "도마뱀": ["스팍", "보"], "스팍": ["가위", "바위"]}  
def make_table(choices, beats):           # 딕셔너리 규칙 → 2차원 판정표 자동 생성  
    table = []  
    for me in choices:                    # 행: 나  
        row = []  
        for cpu in choices:               # 열: 컴퓨터  
            if me == cpu:  
                row.append(0)             # 비김  
            elif cpu in beats[me]:  
                row.append(1)             # 이김  
            else:  
                row.append(2)             # 짐  
        table.append(row)  
    return table  
TABLE = make_table(CHOICES, BEATS)  
def run_tests():                          # 판정표 대칭성 자동 검사  
    for a in range(len(CHOICES)):  
        assert TABLE[a][a] == 0 and TABLE[a].count(1) == 2  
        for b in range(len(CHOICES)):  
            if a != b:  
                assert {TABLE[a][b], TABLE[b][a]} == {1, 2}

## Ⅶ. 교사 수업 설계 및 운영 유의사항

1. 수업 설계 측면  
• 이 수업의 핵심은 ‘새 게임을 많이 만드는 것’이 아니라 ‘같은 게임을 더 좋은 구조(함수·자료구조)로 다시 만드는 경험’이다. 기본 버전과 개선 버전을 나란히 비교하게 한다.  
• 차시마다 PRIMM(예측–실행–탐구–수정–만들기) 흐름을 유지한다. 바로 코드를 작성하게 하기보다 완성 코드를 먼저 읽고 예측하게 하면 초보 학습자의 인지 부담이 줄고, 수정 과제로 자연스럽게 작성 단계로 넘어갈 수 있다.  
• 위키독스 각 차시 페이지의 ‘전체 코드’는 복사해서 바로 실행할 수 있으므로, 타이핑 시간 대신 코드 읽기·추적·수정에 시간을 쓴다.  
• 수행평가 채점 기준(다차원 데이터 구조 25점)과 연결되도록, 3~4차시 설계에서 딕셔너리·2차원 리스트 활용을 반드시 계획하게 한다. 9차시(던전 탈출, BFS)는 심화 선택 차시로 운영할 수 있다.  
2. 수업 운영 측면  
• 2인 짝 프로그래밍으로 운영하고 드라이버·내비게이터 역할을 활동마다(약 5~10분) 교대한다. 수행평가는 개인 산출물 기준이므로 짝 활동 후 개인별 코드를 완성·제출하게 한다.  
• 교사 순회 시 정답 대신 “이 함수는 무엇을 돌려주니?”, “이 값은 몇 행 몇 열이니?”와 같은 질문으로 피드백한다.  
• 진도가 빠른 학생에게는 코딩 테스트 도전 문제·5가지 가위바위보·BFS 최단 거리를, 느린 학생에게는 Parsons 문제(코드 줄 배열하기)·빈칸형 활동지를 제공한다.  
• 기억력 게임의 화면 지우기(print("\n" * 40))는 IDLE에서 스크롤하면 보일 수 있고, 행맨의 ♥ ♡ 기호는 한글 자판에서 ㅁ + 한자 키로 입력한다는 점을 미리 안내한다.  
3. 생성형 AI 활용 및 평가 유의사항  
• AI는 ‘정답 코드 생성기’가 아니라 ‘질문형 튜터’로 활용하게 한다. 정답 코드 요청 대신 오류 메시지 해석·확인할 부분에 대한 힌트를 묻게 하고, 학번·이름·학교명 등 개인정보는 입력하지 않는다.  
• AI 활용 시 AI 활용 기록표를 작성하게 하고, 제출 코드에 대해 교사가 질의(“이 줄은 무슨 일을 하니?”)하여 설명하지 못하는 부분은 채점에서 제외될 수 있음을 사전에 안내한다.  
• 수행평가는 수업 시간 내에 진행하고, 수업 종료 후 활동지를 제출받는다. 과정 중심 평가로서 교사 관찰 기록을 함께 남긴다. 결시·학적변동 학생 처리는 학교 학업성적관리규정을 따른다.
